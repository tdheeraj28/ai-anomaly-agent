# AI Anomaly Agent — Portfolio Project

A deployable Streamlit application for screening tabular business data for unusual records. It combines data-quality profiling, unsupervised anomaly detection, visual exploration, CSV export, and a transparent analyst-style investigation brief.

## Features
- Upload any CSV or load synthetic ecommerce order data.
- Profile row/column counts, missing cells, duplicate rows, and per-column quality.
- Select numeric features and tune the expected anomaly proportion.
- Detect unusual records with Isolation Forest.
- Explore typical versus flagged records in interactive charts.
- Read a deterministic investigation brief and download flagged rows.
- Includes tests for data profiling, detection, and reporting.

## Technology
- Python
- Pandas and NumPy
- Scikit-learn: median imputation, standard scaling, Isolation Forest
- Streamlit for the web UI
- Plotly for interactive charts
- Pytest for basic automated tests

## Run on Windows
Open PowerShell in the project folder:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

If `py` is unavailable, install Python 3.11 from python.org and enable the option to add Python to PATH. The commands intentionally do not require PowerShell environment activation.

## Run tests
```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## Deploy on Streamlit Community Cloud
1. Create a GitHub repository and upload all files in this folder.
2. Open Streamlit Community Cloud and connect your GitHub account.
3. Create a new app, choose the repository and branch, and set the main file to `app.py`.
4. Deploy. This project does not require an API key.

## How it works
1. The user selects numeric features from the uploaded dataset.
2. Values are coerced to numeric; invalid entries become missing.
3. Missing values are imputed with the median.
4. The selected features are standardized.
5. Isolation Forest estimates which records are easiest to isolate from the main data pattern.
6. The app marks predictions as `is_anomaly` and creates a relative `anomaly_score` for ranking.
7. The report compares medians and recommends human investigation steps.

## Important honesty / limitations
- The included dataset is synthetic and should not be represented as real company data.
- The report is rule-based, not generated by an LLM. The current application is an ML-powered anomaly-screening assistant, not a fully autonomous AI agent.
- `contamination` is a modeling assumption used by Isolation Forest, not a measured business anomaly rate.
- A flagged row may be a legitimate rare event. The model does not prove fraud, error, or causation.
- This first version models numeric columns only; date and category are shown for context, not used by the detector.
- For a serious production version, add labelled evaluation data, access controls, data validation, monitoring, logging, and human review.

## Email alerts
The dashboard includes a **Send anomaly alert email** button. It emails a short summary and up to 10 flagged record IDs only after an explicit click; it does not send repeatedly on normal app reruns.

### Configure Gmail SMTP locally
1. Enable 2-Step Verification on the sending Google account.
2. Create a Google App Password in Google Account security settings. Do not use your normal Gmail password.
3. Copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml`.
4. Fill in `SMTP_USERNAME`, `SMTP_PASSWORD`, `ALERT_FROM`, and `ALERT_TO`. Keep host `smtp.gmail.com` and port `587` unless your email provider says otherwise.
5. Restart Streamlit, run detection, and click **Send anomaly alert email**.
6. Never commit `.streamlit/secrets.toml`; it is excluded by `.gitignore`.

### Configure on Streamlit Community Cloud
Add the same TOML key/value settings in your app's Secrets settings. Never store credentials in GitHub.

Email requires valid SMTP credentials and network access. A flagged record is a lead for review, not proof of fraud or error. This project currently analyzes uploaded CSV files; it does not continuously monitor a live data source.
